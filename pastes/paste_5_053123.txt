# Steam 数据获取与推荐策略（最终优化版）

## 默认路径（无需额外配置，立即可用）

1. **知识驱动优先**
   - 基于训练数据与本地知识立即生成推荐列表。
   - 输出时增加 **数据新鲜度** 标签：
     - 🟢 实时获取
     - 🟡 推测（基于已知版本/历史数据）
     - 🔴 需核实（数据可能已变动或缺失）
   - 仅当以下情况之一发生，才主动提议联网核实：
     - 用户明确要求“查最新评价/价格”。
     - 某游戏的关键数据距今已超过 6 个月，且被高频推荐。

2. **按需执行轻量脚本**
   - 用户要求核实 ≤3 款游戏时，触发稳健的数据获取脚本（`fetch_game_details`）。
   - 脚本特性：
     - 超时 15 秒。
     - 最多重试 2 次（指数退避）。
     - 字段缺失直接标记 `null`，不重复请求。
   - 若脚本失败 → 诚实告知无法实时获取，附上 Steam 页面链接供用户自行查看。

3. **预算控制**
   - 单次推荐任务的全部工具调用总时长不超过 60 秒。
   - 超时则终止工具调用，返回已有结果并说明部分数据需核实。

## 进阶路径（高可靠性、低延迟，需一次性设置）

### 选项 A：用户提供 Steam Web API Key
1. 优先使用用户自己的 API Key 调用 `api.steampowered.com`（合法、不限流）。
2. 实时获取游戏详情、评价、价格，直接输出 🟢 新鲜数据。
3. 回退策略：API Key 失效或请求失败 → 自动降级到默认路径的方案2（轻量脚本）。

### 选项 B：配置定时缓存任务
1. **设置 cronjob**（每周执行）：
   - 拉取 Steam 热门榜单（Top 200-500）+ 用户常查询的游戏列表。
   - 解析并缓存三张表：
     - 游戏元数据（名称、类型、发布日期）— 月更新
     - 最新价格（含区域）— 日更新
     - 评价摘要（好评率、总数、近期趋势）— 周更新
   - 数据源：Steam Store API + IsThereAnyDeal / SteamSpy 快照（避免单一依赖）。
2. **推荐时优先读缓存**：
   - 命中缓存且时间戳未过期 → 🟢 直接使用。
   - 缓存缺失或过期 → 回退到默认路径的知识驱动（🟡），并触发一次单游戏轻量更新。
